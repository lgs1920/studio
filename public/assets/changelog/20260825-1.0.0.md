## Studio 1.0.0 — Replay Recording, Timeline Editing, Deployment Reliability, and Optional Cesium ion

## Release Scope

- Studio 1.0.0
- Backend 0.8.0
- Site 2026-08-25

## New Features and Improvements

### studio

- Replay timeline editing now provides transient controls to fit the complete duration horizontally or maximize the number of visible tracks vertically, with accessible Web Awesome tooltips.
- Timeline clip movement and resizing now snap to major ruler units within an eight-pixel magnetic threshold, with a transient indicator showing the edited edge during resizing.
- Controlled timeline updates preserve the user's local ruler zoom, and deleting clips that leave only one distinct widget dissolves the group back into a standalone track.
- Replay preparation now uses a normalized timeline projection with synchronized track actions and a branded locked timeline preview.
- Camera preparation now stabilizes around the departure point, exposes the camera axis and lateral angle, and prevents the camera from moving below terrain.
- Standard video and synchronized Replay video workflows now have separate entry points.
- Widget resizing and capture now preserve non-distorting dimensions and use SnapDOM geometry as the authoritative size.
- Studio initialization progress is now displayed on the welcome screen, and hideable widgets expose explicit hide and show controls.
- Side drawers can now be resized within their available layout space.

- Draft and HQ replay videos now preserve journey metadata, including draft status, journey title, date and location details, album, genre, publisher, and encoder information.
- Replay and map controls now expose dedicated focus actions while an active rotation is running.
- HQ replay capture now waits for visible 2D imagery and 3D tiles before encoding frames.
- Crop zones now remain fully contained within the browser viewport during initialization and resize operations.
- Error dialogs now expose structured diagnostics for file and runtime failures.
- PWA updates are detected when the application version changes, and update notifications remain available in a persistent dialog.
- PWA icons, splash-screen media, and installation guidance now follow the updated Studio branding and installation flow.
- Layer-specific provider credits now support dedicated Google Maps attribution in map displays and exported reports.
- Video editing now groups ratio, quality, and FPS controls in a compact HUD, with popup placement and labels adapted for mobile screens.
- Scene widgets now normalize their position, scale, margins, and bounds after layout changes so on-map controls remain visible.
- Replay recording supports standalone crop-zone video recording without requiring an HQ export.
- Replay styling now includes Glow and Neon effect controls for traces and markers.
- The Replay drawer exposes a dedicated Style tab for replay effects and opacity controls.
- Replay and video workflows now isolate backend SMTP environment configuration from Studio processes.
- Launch registration storage can persist outside versioned release directories during deployment.
- Studio attribution now includes photography and Three.js open-source credits.
- The Studio welcome experience can reuse the Site's animated Three.js route as a persistent backdrop, with media and build credits.
- Welcome videos now crossfade smoothly, preserve their initial presentation, and use updated Studio branding and slogan.
- Welcome loading feedback now communicates initialization status and readiness before entering Studio.
- Widget and video composition now preserve independent horizontal and vertical scaling and refresh captured dimensions after layout changes.
- Replay widget capture now handles rehydrated widgets, asynchronous canvas initialization, and SnapDOM resource pre-caching more reliably.
- Backend initialization support requests now include the relevant error diagnostics in the generated email.
- Replay HQ recording now uses an isolated recording camera and a live monitor with Picture-in-Picture support and a widget fallback.
- Replay recording now uses a canonical frame and camera pipeline, with more reliable crop interactions, widget composition, and journey report exports.
- Cesium ion is now optional: Studio starts with non-ion providers and requests a provider-scoped token only when an ion-dependent layer is selected.
- Closing Studio now confirms whether local data should be cleaned before quitting, with a recovery path when cleanup fails.

See [Studio changes from 1.0.0-beta.3 to 1.0.0](https://github.com/lgs1920/studio/compare/1.0.0-beta.3...1.0.0) on GitHub.

### backend

- Rendered localized form emails are accepted through a generic backend mail envelope.
- Launch registration now supports confirmation, resend, cancellation, and persistence outside release directories.
- Backend administration commands can list pending registrations and clear selected registrations with scoped actions.
- Visitor acknowledgement and support messages are separated, with site links derived from deployment configuration.
- Backend statistics APIs now provide real-time counts and historical period data.
- Backend deployment monitoring now checks liveness every five minutes and can perform a controlled PM2 restart after a confirmed outage.
- Backend PM2 processes now use persistent rotating error logs, with monitoring and restart results recorded without exposing secrets.
- The obsolete FFmpeg video-conversion pipeline has been removed from the backend integration.
- Backend deployment now uses PM2 7.0.4 for process management.

### site

- Help routes are available again in the production site while the intended registration restrictions remain in place.
- The site now provides Contact and Launch Registration pages with refined registration presentation, localized page data, French copy, and registration guidance.
- Contact form delivery now exposes scoped diagnostics and manages status visibility consistently.
- Site backend endpoints are read from Studio configuration, with a scoped recovery dialog for backend availability issues.
- Public statistics now include live counters and historical charts.
- The public changelog is paginated for easier navigation.
- Site branding has been refined and the site logo assets have been migrated to PNG.
- Hero banners now support rotating media backgrounds from a shared catalog.
- Localized form-mail catalogs now cover visitor acknowledgements, support messages, cancellation links, and launch-registration confirmation.
- Launch registration now includes localized cancellation and confirmation pages, pending-registration resend handling, and responsive mobile navigation.
- An animated neon route is available across the generated site heroes with a non-WebGL fallback.
- Credits pages are available in English and are linked from the site footer.
- Site-wide search now supports guide-scoped queries, localized result categories, highlighted matches, and global-dialog handoff from 404 pages.
- Help navigation, guide breadcrumbs, and entry points have been reorganized, including quick-access cards for the main guide areas.
- Homepage and registration hero visuals, copy, animations, branding, and spacing have been refined for clearer navigation and presentation.
- The FAQ now includes the Grande Sûre story and its accompanying photo.
- Studio and registration presentation content is now aligned across English and French, with refreshed privacy, access, and responsive layouts.
- Registration confirmation and revocation pages now use a simpler full-width status presentation without duplicate hero content.
- Public releases are ordered by publication date in the changelog.

See [Site changes from the previous release reference](https://github.com/lgs1920/site/compare/682d1bc74c96493005999cf226e5033ff0f18ae1...c6aeacf5c7715b0152a25c4a0c5a507e31e44e77) on GitHub.
