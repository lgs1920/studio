# Font Awesome Configuration

## Integration

- **Method:** Web Awesome `WaIcon` React wrapper with the shared Font Awesome definition registry and Web Awesome's default resolver.
- **Version:** Font Awesome packages 7.3.1; Web Awesome 3.14.0.
- **License:** Pro.
- **Kit ID:** `eb5c406148` (custom icons and the default CDN resolver).
- **Families:** classic, duotone, brands.

## Defaults

- **Style:** regular for the camera adjustment overlay.
- **Family:** classic.

## Import Pattern

```jsx
import { WaIcon } from '@awesome.me/webawesome/dist/react'

<WaIcon name="ruler-vertical" variant="regular" />
<WaIcon name="question" variant="regular" />
```

## Conventions

- Use kebab-case Font Awesome `iconName` values, and omit `family` for classic icons.
- Register concrete icon definitions in `src/Utils/LGS1920IconLibrary.js` and pass them to the generic resolver in `src/Utils/useWebAwesomeKits.js`.
- The `ruler-vertical` and `question` regular definitions are bundled from `@fortawesome/pro-regular-svg-icons`, so their availability does not depend on the remote Kit subset.
- Custom classic and duotone definitions come from `@awesome.me/kit-eb5c406148`.
- Missing local definitions delegate to Web Awesome's default resolver. Do not assume a standard icon belongs to the Kit merely because its npm package is installed.
- The implementation contract is documented in `tech-doc/specs/ui-widgets/CORE-UI-ICONS-SPEC.md`.
