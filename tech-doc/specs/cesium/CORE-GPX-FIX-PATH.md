# Manual GPX path corrections

Fix Path lets a user correct a route locally in map space and adjust the elevation used by the profile. Open it from the map point context menu or press `F` when the current Journey has tracks. The source GPX remains unchanged; each completed edit is validated, stored on the Journey, and applied as derived track content immediately.

## Editing a Journey

Opening Fix Path temporarily hides the Journey Toolbar and restores its previous visibility on exit without changing the saved setting. Opening Fix Path pans the map to the persisted current section, or the first available section when none is saved, while preserving camera orientation and scale. Cesium navigation remains available while the user selects a route or correction point. Shift-drag or Alt-drag draws a lasso; Ctrl+Shift-drag or Ctrl+Alt-drag draws a screen rectangle. Shift and Ctrl gestures select visible Journey points when they start over the route, or correction points when they start over a correction marker. Alt gestures select correction points in the current section. Lasso selection can be drawn freehand or outlined with successive clicks and closed with a double-click. The map displays a live guide while a lasso is active, and Escape cancels it. Shift-click on a correction marker toggles that marker in the selection. Explicitly selecting a previously removed source point restores it as an unmodified point; Undo restores its prior removed state. Added points that bridge other sections merge them automatically, and the point list refreshes to match the resulting section. The source-point projection and terrain-visibility checks run in small batches so a long GPX does not block the interface. Selected route points are immediately represented by their section markers; temporary white source squares and orange pending-point markers are not displayed. Clicking a map point preserves the current camera view and zoom. Explicit section navigation pans the map to the selected section while preserving zoom, orientation, and widget position.

The editor stores every source vertex between a section's endpoints as a section point, including vertices that have not been fixed or removed. When a valid saved section has a modified source point at an endpoint, loading adds one unmodified neighboring source vertex at that edge when available, within the section-length limit, and without overlapping another section. The active and inactive route lines are magenta and gray. In the current section, unmodified or reset source points are blue diamonds with black 2 px borders, and moved points are magenta circles with white 2 px borders. Selecting a point changes its fill to chartreuse and its border to black while preserving its status shape: selected unmodified points remain diamonds and selected moved points remain circles. In non-current sections, unmodified points are gray diamonds with white 2 px borders and moved points are gray circles with white 2 px borders. Newly created source points and source points added while extending a section start as unmodified; they change to moved only after they are dragged. Point sizes do not change with map zoom. Every point marker uses the same slight lift above loaded terrain. List indicators mirror the marker shapes and use Font Awesome Duotone colors: selected points use chartreuse and black, unmodified points use blue and black, moved points use magenta and white, and removed points use the danger colors. Source vertices inside a section are represented by its section points instead of duplicate white source markers. Points in the current section can be selected and dragged. Points in non-current sections cannot be dragged; clicking one selects it, makes its section current, and displays that section in the widget. Sections whose source-point membership is contiguous merge automatically, regardless of whether their points have been moved. Dragging a source vertex beside existing corrections also merges the affected local sections and retains their point states. Erase removes an individual point from section membership. If this leaves disjoint runs of source points, each run remains a separate section, and the widget displays the resulting current section. The point-row Delete shortcut instead marks a point removed without deleting its row; reset restores it. A right-click on a correction point also offers Remove. A Ctrl+Shift or Ctrl+Alt rectangle, or a Shift lasso, selects route points to create or extend a section; source vertices in the selected range start as unmodified diamonds. Corrections are split into local sections so a single edit cannot span an unexpectedly long part of the route. The default source-route limit is 500 m. Application Settings lets the user change it from 50 m to 5,000 m in 10 m steps; the preference is retained when settings are synchronized with defaults.

The Fix Path panel is a draggable scene widget. Its header contains Help and Close actions. A full-width toolbar below the header contains Undo/Redo, section navigation, current-section correction visibility, and Erase. It displays one active section at a time. Previous/Next navigate in Journey travel order; first/last shortcuts appear when there are more than two sections. Section navigation centers the selected section while preserving camera zoom, orientation, and widget position. Map-point clicks preserve the current camera view. Sections created while the editor is open immediately join this navigation order. Clicking a point in a non-current section selects it, activates its section, and displays that section in the widget. Selecting a saved correction point exits section drawing so later map clicks cannot add stray control points. When marker hit areas overlap, the closest visible marker receives the selection and drag. The eye control shows or hides the current section's corrected map geometry and editing markers. This is a temporary rendering choice; saved corrections stay accepted and continue to affect statistics and Replay. Erase removes individual point membership from the active section; removing a point can split one section into contiguous sections. Undo and Redo cover all correction edits, including membership changes, additions, deletions, merges, movement, reset, and height changes. Corrections from every track remain applied and are saved together after each completed edit.

New correction points use the current Cesium terrain height beneath their clicked coordinates when available. Each active section's list includes all its points and has Lat, Lon, and Height columns without Journey or segment labels. Height is a Web Awesome number input displayed in the elevation unit configured in application settings and converted to metres when saved. The list scrolls independently inside the widget, with enough end padding to reveal the last row fully at maximum scroll. Clicking a row selects its corresponding map point. Selecting a point changes its colors to chartreuse and black while preserving its moved or unmodified shape: an unmodified point remains a diamond and a moved point remains a circle. The panel reports the selection count and uses matching Font Awesome Duotone shapes and colors. Source points included when creating or extending a section start as unmodified; manually positioned control points remain moved. With the widget focused, Ctrl+A selects all non-removed points in the active section. Dragging any selected point moves the whole selection by the same map and height offset. Lat and Lon are read-only text fields. From any field in a row, Ctrl/Cmd+R resets the point and Delete marks it removed. Removed rows remain disabled, show a danger-colored duotone circle, and can be restored with Reset.

After each completed edit—moving a point, creating or extending a section, erasing or restoring a point, resetting a point, or committing a height—the editor validates every correction, persists the Journey, and redraws the route before accepting another edit. Any remaining non-removed correction enables `fixPathEnabled`, so the new route geometry is immediately used by the map, statistics, and Replay. The eye control changes only the temporary map rendering of the current section and its editing markers; it never changes correction data or whether accepted corrections apply to statistics and Replay. Points added by extending a section start unmodified and are not selected automatically. Selected source points become part of a section immediately; temporary white source and orange pending markers are not shown. The height field updates its preview while typing and persists on the Web Awesome `change` event. The editor reports while the Journey is being updated; if validation, persistence, or redraw fails, the editor stays open and the point edit remains available for correction or retry. The X action closes the editor after the latest edit has been applied. Corrections are loaded the next time the Journey is opened and remain visibly distinct from source vertices. The Journey's Apply path corrections switch can still turn saved corrections off outside the editor; making an edit in Fix Path enables the remaining corrections again so the visible route reflects that edit.

## Stored data

`fixPathCorrectionData` contains a revision and correction sections grouped by track slug. Its optional `currentSection` stores the `{trackSlug, correctionId}` of the section currently open in the editor, so reopening Fix Path for that Journey restores the same section and pans the map to it while preserving camera orientation and scale. If the saved section no longer exists, the first available section is used. Normalization drops this identity if its section no longer exists. Each section records the source geometry segment and endpoint indices, a fingerprint of the covered source coordinates, and ordered points. Every point stores its route progress, `[longitude, latitude, height?]`, and `fixed` and `removed` booleans. Source vertices also store their source index. A point's membership in a section is independent of its flags. Unfixed points remain listed and drawn but do not guide the curve; fixed, non-removed points are interpolation anchors. Removed points are hidden and excluded from the interpolation. Coordinates without an explicit height inherit a height interpolated from the source GPX profile. Legacy points without flags normalize to `fixed: true` and `removed: false`.

The fingerprint prevents a correction from being applied to a different route after the source track changes. Stale sections are skipped rather than moved to new source indices. Multiple sections on a track must be separate, non-overlapping, and separated by at least one unassigned route point.

## Applying edits

The interpolation creates a smooth, Catmull–Rom curve in a local horizontal projection and interpolates elevation through the same ordered anchors. Unfixed source vertices inside a section are recalculated from its fixed anchors. Section endpoints are editable and can also be fixed anchors. Render smoothing splits the displayed path at fixed source vertices so those vertices remain exact rendered points, and render-size sampling retains those anchors. Timestamps, extra coordinate dimensions, properties, and the original GPX feature remain intact. This keeps the original track as the persistent source while statistics and display use the corrected derived feature.

`getCorrectedTrackContent()` is the shared source for Journey metrics, Cesium rendering, and Replay path sampling. The `fixPathEnabled` Journey flag applies all saved track corrections or none. Saving an edit increments the correction revision so rendered geometry and Replay samplers refresh immediately. Ordinary load and Replay do not start terrain analysis or asynchronous correction work.
